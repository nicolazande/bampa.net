The architecture

EPYC plus several GPUs:
the best of both worlds.

A large model isn't sized by the power of the graphics card, but by memory: how much there is and how fast it is. That's why we combine GPU memory with the RAM of an 8-channel server processor.

GPU

Fast video memory

This holds the most-used layers of the model and the users' context. More GPUs mean more memory and more people served at once, each with their own space.

EPYC · 8 channels

Large server RAM

Hundreds of GB of error-correcting memory for models that don't fit in the GPUs, long contexts, document indexes and always-on agents.

Platform

Grows with you

RAM, GPUs and storage are added one at a time. Start with what you need today and expand when usage calls for it.

The two-model workflow

The cloud designs the method.
The local model does the work.

When you need the most capable model on the market, use it only to invent the procedure, on a non-confidential example. Then the local model applies it to hundreds of real files that never leave.

  1. Cloud

    Discovery

    understands the problem on a clean example

  2. Cloud

    Formalisation

    writes rules, tools, examples and tests

  3. Local

    Execution

    applies the procedure to all your data

  4. Local

    Verification

    checks format, consistency and errors

  5. Cloud, if needed

    Hard cases

    only the few ambiguous cases, anonymised
